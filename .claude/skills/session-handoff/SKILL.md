# session-handoff — 次のセッションのために docs を最新化する

目的地: **次のセッションが session-catchup したとき、VCS と照合してもズレが出ない状態。**

## 手順

1. **棚卸し**: `git status --short`、`git log --oneline -10`、`ls -la docs/`。未追跡の doc が無いか見る。
2. **handoff.md を書き直す**: `最終更新` を今日の絶対日付に。状態表を実態（コミット・検査結果）に合わせる。**検査の件数や `doctor` の OK/WARN/FAIL の内訳のように、コマンドを 1 回叩けば分かる数値は手で書かない**（書いた瞬間から腐り始める）。状態表の出典列に叩くコマンドを書き、数値は次のセッションが都度そのコマンドで確認する。`NEXT` を依存順に。順序制約（「A を先にしないと B が切り分けられない」）は最優先で書く。人間の判断待ちは `未確定事項` へ。
3. **確定事項を書き戻す**: 会話で合意した仕様・設計は spec/docs に書き戻す。決定は `docs/decisions/` に 1 ファイル。`.harness/state/` を使っている場合、確定したものは JSON から消して docs に移す。
4. **罠を残す**: このセッションで踏んで解決した罠を `docs/learnings.md` に「症状 → 原因 → 再発したら」の形で。プロジェクト非依存なら `[harness候補]` を付ける。
5. **索引を合わせる**: doc を足した／消したなら `docs/README.md` の表を直す。
6. **ハーネスの健康**: `harness status` を実行。managed ファイルに drift があれば、上流に戻すか元に戻すかを報告に書く（黙って放置しない）。
7. **コミット**: プロジェクトのコミット規約に従い docs をコミットする。コミットしない判断をしたなら理由を報告に書く。
8. **触らなかったものも報告**: 確認したが意図的に更新しなかった doc を挙げる。次のセッションが同じ確認を繰り返さないため。

## 書かないもの

セッションの時系列ナラティブ、git log が語ること、コードを読めば分かる構造。
