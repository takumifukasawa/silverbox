# spec — 何を作るか（唯一の正）

「何を作るか」はここにだけ書く。会話で合意した変更は、ここに**書き戻す**まで「決まっていない」。
準備フェーズで依頼内容と 1 件ずつ突き合わせ、乖離を潰してから実装に入る（手戻り削減に最も効く）。
既に別の場所に仕様がある（例: `docs/GAME.md`）なら移さなくてよい。下の表に行を足してリンクすれば、それがこの索引の一部になる。

「どう作るか」の規律は、効かせたいパスの `AGENTS.md` に書く（一覧: `../rules/README.md`）。spec と規律が矛盾したら**規律が勝つ**。
画面があるなら UI プロトタイプ（画像・Figma のエクスポート・HTML）も仕様源の一部としてここに置くか、リンクを書く。エージェントは文脈に入らないものを知らない。

| | | 草案 / 合意済 / 実装済 |

## 1 つの spec の書き方

- 目的（誰の何が変わるか）
- 受け入れ条件（検査・テストで確認できる形。曖昧語を使わない）
- 範囲外（やらないこと）
- 未確定事項（人間の判断待ち。決まったら本文に移して消す）
