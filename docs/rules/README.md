# rules — パス限定の規律の一覧

トップの `AGENTS.md` に書くとすべてのセッションに載ってノイズになる規律は、**効かせたいディレクトリの `AGENTS.md`** に置く。

読み込まれ方はエージェントで違う:
- Claude Code: そのディレクトリのファイルを読んだ時点で、隣の `CLAUDE.md`（`@AGENTS.md`。`harness update` が自動生成）経由で載る。
- Codex: **ルートから cwd までの連鎖**しか読まない（合計 32 KiB 上限）。cwd がルートのままだと載らないので、そのディレクトリを cwd にして起動するか、統括役がこの一覧から該当ファイルを開いて実装役に渡す。

どのエージェントでも確実に効かせたい規律は、文章ではなく `.harness/checks.sh` の検査に落とす。

書くもの（SmartHR の例では データモデル / ドメイン / 境界 の 3 ファイル）:
- 常に守ること（ロックの取り方、スコープ、命名、依存の向き）。spec と矛盾したら**規律が勝つ**。
- **やらないこと**。エージェントは指示以上に作り込もうとするので、入れない実装を宣言しておくと毎回指示しなくても守る。

規律を渡し忘れると、エージェントは「spec に書いていないから自由」と解釈して規律を破る。統括役は spec の節と規律を**必ずセットで**実装役に渡す。

ここはその一覧。規律を足したら行を足す。

| パス | 規律の要点 |
|---|---|
| `src/example/AGENTS.md` | 例: このモジュールは外部 I/O を持たない。依存は `core/` 方向のみ |
